## Что это и чего это не касается

Это исправления и доработки уже существующих экранов: сгруппировать навигацию, вернуть ячейке
стены её собственное управление, объяснить общую шкалу времени, сделать управление ячейкой
обнаружимым, показать журнал событий человеческим языком и закрыть мелкие P2-огрехи (сырые ключи,
жёстко зашитые строки, путь хранилища, узкие вкладки редактора карты). Новых экранов и новых
серверных контрактов здесь нет.

Вне этого плана по решению самого аудита:

- **Семантика `control` и `view_live`** (пустой Control у роли `user`) — это решение о модели прав,
  а не о вёрстке. В Stage 0 оно выносится в отдельный файл `docs/future_plans/`, кода здесь нет.
- **Форма вместо JSON в маршрутизации событий** — это новая функциональность, а не исправление.
  Она уже записана в [12-event-routing-followups.md](../future_plans/12-event-routing-followups.md);
  JSON остаётся основным режимом до отдельного решения.
- **Серверный фильтр журнала по типу и тексту.** Сегодня тип и поиск фильтруют уже загруженные
  страницы; серверного контракта для них нет. Это отдельное изменение VmsMap, вынесенное в
  `docs/future_plans/`.

## Решения

1. **Два пункта P1 — решения, а не код.** Семантика `control`/`view_live` уходит отдельным файлом в
   `docs/future_plans/` (Stage 0), форма маршрутизации остаётся в
   [12-event-routing-followups.md](../future_plans/12-event-routing-followups.md). Этот план
   реализует остальные шесть пунктов P1 и все пункты P2.
2. **Навигация — группы в той же вертикальной панели, без подменю.** Один общий компонент
   группированной навигации для Admin и Operator: заголовок группы, под ним её вкладки. Слаги
   маршрутов не меняются — они часть глубоких ссылок; меняются только подписи и раскладка.
   Заголовки групп: «Devices», «Space», «Video», «Recording & storage», «Events & analytics»,
   «System» у администратора; «Live», «Map», «Events & archive» у оператора.
3. **Полные названия вместо сокращений.** «Cam setup» → «Cameras», «Rec. profiles» → «Recording
   profiles», «Rec. schedules» → «Recording schedules», «ONVIF Cfg» → «ONVIF configuration»;
   админская вкладка «Monitors» называется «Video walls», операторская остаётся «Monitors».
   Испанские подписи сокращаются так же до полных слов; ширина панели растёт, контент остаётся
   `flex: 1`.
4. **Переключатель роли — сегментированный, а не текстовая кнопка 0.7rem.** `ViewControls` получает
   текущее представление и рисует `ToggleButtonGroup` «Operator | Admin» того же размера, что и
   остальные служебные кнопки. Переход по-прежнему проходит через `applyPending`; сегмент Admin
   показывается только тому, кто может администрировать, иначе переключатель скрыт целиком.
5. **`controls` у живого видео — проп с умолчанием `false`.** Ячейка стены отдаёт клики своим
   контролам; единственное место, где родные контролы остаются нужны, — диагностическая страница
   `TestLivePage` (вокруг неё нет продуктовых контролов). Комментарий watchdog'а переписывается:
   пауза больше не приходит от оператора через `controls`, но элемент всё равно может быть
   приостановлен браузером, и это не признак зависшего потока.
6. **Шкала объясняет то, что уже нарисовано, и честно называет неизвестное.** Четыре состояния:
   запись есть, записи нет, архив недоступен (запрос покрытия отказал целиком), камера не ответила
   (в успешном ответе нет её дорожки). Плюс две уже существующие пометки — восстановлено с камеры
   и перекодировано с ROI. Различаются заливкой, контуром, штриховкой, полосой и иконкой, а не
   только цветом. Новых серверных полей и опроса heartbeat нет: «не ответила» — это отсутствие
   дорожки в ответе, а не отдельный статус камеры.
7. **Управление ячейкой — меню, а не одинокая иконка.** Кнопка `MoreVert` заменяет
   `SwitchCameraIcon` и открывает меню «Switch camera / Move / Clear». «Move» включает режим
   переноса: следующая ячейка — цель, `Esc` отменяет; перетаскивание остаётся и работает как
   раньше. Подсказки ставятся на цель, а не на всё видео: пустая ячейка («Click to add a camera»),
   подпись камеры («Click to focus · Drag to move or swap») и кнопка меню («Cell actions»).
   Активная ячейка получает подпись, а не только белый контур.
8. **Журнал: быстрые фильтры на первом уровне, остальное — за раскрытием.** Первая строка: период,
   тип, объект/камера, поиск, Apply. «More filters» раскрывает `Param 0`, `Param 1` и «With
   pictures». Список/галерея и обновление переезжают в заголовок списка, автообновление остаётся в
   его подвале — контрол стоит рядом с тем, на что действует (`CLAUDE.md`). Тип и поиск остаются
   клиентскими по загруженным страницам; это ограничение записывается в `docs/future_plans/`, а не
   выдаётся за серверный фильтр.
9. **`Param` получает смысл из типа события.** Чистый модуль `eventPresentation`:
   - `sensor` → `Param 0` = Contact (`open`/`closed`);
   - `relay` → `Param 0` = State (`active`/`inactive`);
   - `analytics` → `Param 0` = Class (перевод из `analytics.class.*`, иначе сырое значение);
   - `alarm`, `alarm_*` → `Param 0` = Stream, `Param 1` = Trigger;
   - `arming` → `Param 0` = Actor, `Param 1` = Mode (`any`/`armed`/`disarmed`);
   - остальное — прежние `Param 0`/`Param 1`.
   Строка списка и карточка события читаются как «Sensor · Open», а не как протокол.
10. **Свойства события — человеческая строка и сворачиваемый технический блок.** Основное:
    событие, смысловые параметры, приоритет, время, камера/объект; для `sensor` — полярность,
    для `analytics` — класс и уверенность, для `alarm` — конец тревоги, для `arming` — актор,
    режим и срок. Всё остальное — под «Technical details»: `camera_id`, `part_kind`, `token`,
    `polarity_known`, `observed_at`, `kind`, `confidence`, `detection_id`, `reid_object_id`,
    `alarm_id`, `alarm_end_ts`, `until` и неизвестные ключи как есть. Идентификаторы события и
    объекта переезжают туда же из `EventDetailsPanel`.
11. **`streamName` для архивной карточки берётся только у события тревоги.** Для остальных типов
    `param0` — не имя потока; `EventDetailsPanel`/`ArchiveHlsPreview` получают `undefined` и
    выбирают первый доступный поток, как и при отсутствии предпочтения.
12. **«Строка выбрана, архива рядом нет» — отдельное состояние.** Если строка выбрана, а
    `selectedEpisode` пуст, карточки говорят «No archive is linked to this event», а не «Select an
    event row…». Пока маркер объекта ещё грузится (`objects.busy > 0` и `markers[objectId]` нет),
    сообщение не показывается — иначе оно мигает на каждом выборе.
13. **P2 — только отображение.** Новые ключи в `en`/`es`; нормализация пути хранилища при выводе
    (хранимое значение и форма не меняются); подпись окна на шкале; контекст выбора под вкладками
    редактора карты. Модель данных и API не трогаются.

     камера не ответила (штриховка на дорожке + счётчик на объединении), восстановлено с камеры

   одного дня и дата у границ для перехода через сутки. Чистый помощник `windowRangeLabel` рядом с

### Этап 3 — журнал событий

1. **`eventPresentation`** (`components/events/eventPresentation.ts`) — чистый модуль:
   - `eventKind` (перенос `kindOf`), `paramLabels(eventName)`, `paramValue(eventName, raw)`,
     `rowSummary(event)`, `humanProps(event)`, `technicalProps(event)`;
   - переводы имён событий (`sensor`, `relay`, `analytics`, `arming`, `alarm*`) и значений
     (`open`/`closed`, `active`/`inactive`, `any`/`armed`/`disarmed`); неизвестное — сырое значение;
   - тесты на каждый тип, на неизвестный тип и на событие без `extraProps`.
2. **Фильтры**:
   - первая строка: From, To, Type (компактный `Select` с иконками вместо широкой группы кнопок),
     Object or camera, Search, Apply;
   - Object or camera — `Autocomplete` поверх `mapApi.searchDeviceNodes` (минимум 2 символа,

     из выбранного типа, когда тип один, иначе остаются `Param 0/1`;
   - Apply собирает фильтр через чистую функцию `eventsFilterFromState` (тест: период, объект,
     камера без узлов, пустой фильтр).
3. **Список и его контролы**:
   - заголовок списка: количество, переключатель List/Gallery, Refresh; подвал: Load older и
     Auto-refresh;
   - строка события — `rowSummary(event)` и время; объект и картинка остаются;
   - поиск подписан/подсказан как поиск по загруженным событиям (ограничение честно названо).
4. **Карточка события**:
   - `MapEventDetails` показывает человеческие поля и сворачиваемый «Technical details»;
   - `EventDetailsPanel` теряет дубли идентификаторов (они в техническом блоке) и получает
     `streamName` только для события тревоги (решение 11);

     при выбранной строке без эпизода — `events.eventHasNoArchive`, при загрузке маркера —
     промежуточное состояние, при отсутствии выбора — прежний `archive.selectHint`;
   - сквозная проверка deep link P0: холодная загрузка, выбор `eventUuid`, прокрутка, «не найдено»,
     `Back` — не должны измениться.

## Критерии приёмки

**Навигация**

- 14 административных пунктов читаются как 6 групп, 7 операторских — как 3; заголовки групп
  видны, сокращений «Rec.», «Cfg» нет;
- все прежние слаги маршрутов и глубокие ссылки (`?node=`, `?camera=`, `?monitorId=`, `?seekMs=`)
  работают как до изменения; неизвестный слаг по-прежнему уводит на первую вкладку;
- переключение вкладки сохраняет несохранённую правку тем же контрактом, что и раньше; отказ
  сохранения оставляет на месте;
- переключатель Operator ↔ Admin виден, показывает текущее представление, проходит через
  `applyPending`; у роли без `admin` админского сегмента нет;
- испанские подписи полные и не обрезаются.

**Живое видео**

- в ячейке стены нет родной панели браузера; клик по подписи камеры и по контролам ячейки
  срабатывает;
- архивная карточка сохраняет свои `controls`;
- диагностическая страница `TestLivePage` сохраняет возможность поставить поток на паузу.

**Шкала**

- легенда называет запись, пропуск, недоступность архива и отсутствие ответа камеры; состояния
  различаются не только цветом;
- отказ запроса покрытия виден штриховкой и кнопкой повтора, а не пустой полосой;
- камера без дорожки в успешном ответе отмечена как не ответившая, а не как «нет записи»;
- восстановление с камеры и перекодирование с ROI объяснены теми же образцами, что и на дорожке;
- подпись окна показывает диапазон и день; выбранная камера и объединение по-прежнему подписаны.

**Ячейка стены**

- у ячейки с камерой есть меню Switch camera / Move / Clear; пункты без цели скрыты;
- Move: целевая ячейка подсвечена, перенос и обмен работают, `Esc` отменяет;
- Clear очищает ячейку с немедленной записью, как перетаскивание;
- пустая ячейка на доске подсказывает «Click to add a camera»; подпись камеры подсказывает фокус
  и перетаскивание;
- активная ячейка подписана, контур сохранён;
- перетаскивание, фокус и сохранение раскладки не изменились.

**ONVIF Events**

- без камер — «No cameras added yet.»; с камерами без ONVIF — «No cameras with ONVIF connection
  configured»; с ONVIF-камерами без подписок — «No ONVIF event subscriptions yet» и указание на «+»;
- «+» подписан «Add subscription» и отключён с понятной причиной, когда добавить некого.

**Журнал**

- первая строка — период, тип, объект/камера, поиск, Apply; `Param` и «With pictures» — за
  «More filters»;
- строка события читается как «Sensor · Open», «Relay · Active», «Analytics · Person»,
  «Alarm · main · Motion», «Arming · admin · Armed»; неизвестный тип показывает сырые значения;
- карточка показывает человеческие поля; технические — в сворачиваемом блоке с понятными
  подписями; неизвестные ключи не теряются;
- выбранная строка без камеры говорит «No archive is linked to this event», а не «Select an event
  row»; при загрузке маркера сообщение не мигает;
- архивная карточка не ищет поток по `param0` у `sensor`/`relay`/`analytics`/`arming`;
- Refresh и List/Gallery стоят у списка, автообновление — в его подвале;
- deep link со стены по-прежнему открывает журнал с камерой, временем и выбранным событием;
  холодная загрузка и `Back` дают тот же результат.

**P2**

- `events.autoRefresh`, `wall.noCameraSelected`, «Empty slot», «Switch camera» и
  `Camera "..." not found` переводятся; сырых ключей на экранах нет;
- путь хранилища показывается без `..`; хранимое значение не меняется;
- вкладки редактора карты подписаны коротко, под ними назван контекст выбора (или «Nothing
  selected»);
- испанский проход: новые строки переведены, ни одна не осталась английской.

## Что не входит

- Семантика `control`/`view_live` — отдельный документ и выдача прав, без кода здесь.
- Форма вместо JSON в маршрутизации событий — новая функциональность, JSON остаётся экспертным
  режимом; см. [12-event-routing-followups.md](../future_plans/12-event-routing-followups.md).
- Серверный фильтр журнала по имени события и тексту — отдельное изменение контракта VmsMap.
- Трёхсторонний диалог «сохранить / отменить / остаться» — решение P0 остаётся в силе.
- Переделка редактора карты, аналитика без воркера, полная проверка архива, узкие экраны,
  клавиатурная навигация и контраст — раздел «Что осталось» аудита.
- Глобальный канал ошибок и снекбар — P0 решил иначе (сообщение у панели).
- Переименование слагов, Dapr app id, образов и сервисов — это миграция установок, а не tidy-up.
