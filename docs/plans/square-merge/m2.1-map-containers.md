# M2.1 — контейнеры на карте (зоны) и уровни детализации (детальный план)

> Часть плана [Square → ta_vms](README.md); ссылки «§N» ведут в его разделы.
> Файлы — ориентиры, не полный перечень. Шаги отмечаются ✅ по мере исполнения; «Ход работы» —
> в конце. Майлстоун выполняется **после вливания M4 в `master`**: он опирается на фронтенд M4.

§4.2 сейчас рисует «один уровень за раз» как «только прямые дети пространства», а §4.3
фильтрует по уровням масштаба только произвольные фигуры. Поэтому сценарий Square
«город → район → здание → камера» на одной карте не работает: узел-контейнер (полигон, круг,
иконка) может быть родителем в дереве, и тревоги по нему всплывают, но его дети на холсте не
рисуются; камера не может быть его ребёнком; уровни масштаба не скрывают камеры и футпринты;
входа в контейнер нет.
M2.1 развязывает «где объект нарисован» и «чей он в дереве», учит холст рисовать весь `canvas_id`,
распространяет уровни масштаба на все виды узлов и добавляет кнопку «Войти».

**Что уже есть и переиспользуется:**

- **Одно дерево, тип родителя не важен.** `objects(id, parent_id, owner_id, name)`; вид узла —
  боковые таблицы. Агрегация тревог идёт по `parent_id` без учёта вида
  (`VmsMap/Db/Services/AlarmAggregation.cs`, `StatesUpdateService.RecomputeAsync`), права
  наследуются так же (`RightsService`). То есть любой узел уже может быть родителем, и тревога
  ребёнка уже поднимается до него.
- **Пространство — холст и футпринт одновременно.** `spaces` + `geo_objects`; вложенный план
  рисуется на родителе полигоном (`SpatialDb.UpsertSpaceAsync`), а его дети живут в собственной
  системе координат. Футпринт краснеет и пульсирует по `children_alarms`
  (`web_srv.client/src/map/footprints.tsx`, набор `alarmed` в `MapsOperatorPanel.tsx`).
- **`canvas_id` у каждой фигуры.** `CanvasResolver` при каждой записи геометрии пишет ближайший
  холст-предок (пространство или мнемосхему). Сегодня его **не читает ни один запрос** — он и был
  задуман под «запросы по области внутри одного холста» (README §4.1).
- **Пространственный запрос и наблюдение.** `GetByBox` умеет бокс, зум, id, зону и права
  (`MapServiceImpl.Reads.cs`, `GeoService.GetGeoAsync`); `Watch` по боксу — тот же запрос
  (`Watch/MapWatchPoller.PollBoxAsync`). Холст их пока не использует: он грузит прямых детей.
- **Справочник уровней.** 190 строк «все пары 1–19»; клиент фильтрует фигуры по диапазону зума
  (`map/FiguresLayer.tsx`); `GetObjProps` отдаёт `zoom_min/zoom_max` фигуры узла.
- **Мнемосхемы уже умеют то, о чём речь, и не меняются.** У ребёнка есть `region_id`
  (`diagrams.region_id`, доля региона родительского типа), `DiagramElement` ставит его в регион
  без отдельного рисования, глубина 0–3, покраснение родителей по тревоге — `nodeStyle`.
  Регионы — механизм мнемосхем; на карту он не переносится (см. решения).

**Границы.** Новых сервисов, обязательных переменных, миграций и изменений в `../ta_install`
нет. Мнемосхемы, их регионы и глубина 0–3 — вне области. Вложенные пространства (планы со своей
картинкой и системой координат) остаются как есть. Английская документация (`docs/maps-and-plans.md`)
правится здесь же, чтобы M5 не унаследовал противоречий.

## Решения

- **Контейнер — обычный узел с детьми, и его форма не важна.** Это может быть полигон, круг,
  иконка или узел без фигуры; нового вида узла и боковой таблицы нет. Дерево, права и тревоги уже
  тип-агностичны, «вид узла» остаётся прежним (`figure`, `object`, `space`, …).
- **Холст — единица рисования.** На холсте рисуется всё, чей `canvas_id` равен открытому
  пространству, **на любой глубине дерева**, а не только прямые дети. Правило §4.2 «рисуется один
  уровень за раз» уточняется: один **холст** за раз; вложенные пространства остаются отдельными
  холстами и футпринтами. Так `canvas_id`, который уже пишется, наконец становится тем, для чего
  он заведён.
- **Место на холсте ≠ место в дереве.** Для камеры, ориентира и любой фигуры холст берётся из
  `geo_objects.canvas_id`, а `parent_id` — это владение для тревог, прав и «контейнер». Миграция
  не нужна: `canvas_id` заполняется при каждой записи фигуры. Запросы, которые сегодня выводят
  пространство из `parent_id` (`PlacedReferenceAsync` и родня), переводятся на `canvas_id`.
- **Вложенность — только дерево (решение пользователя 2026-10-31).** Геометрия ничего не решает:
  объект может лежать внутри полигона и не быть его ребёнком, и наоборот. Родителя задаёт
  администратор: новый объект создаётся под выбранным узлом (или под пространством, если ничего не
  выбрано), существующий переносится действием «Переместить в…». Геометрического резолвера
  контейнера нет.
- **Уровни масштаба — для всех видов узлов.** Узел без уровня виден всегда; узел с уровнем виден,
  пока зум Leaflet попадает в диапазон `levels`. Фильтр клиентский, как у фигур: данные холста
  грузятся один раз, при зуме меняется только видимость. «Убрать уровни — всё видно сразу».
- **«Войти» = увеличить зум, а не вписать полигон.** Клик по карте только выбирает. У выбранного
  контейнера (и у тревожного объекта) есть кнопка «Войти»: она повышает зум до уровня, на котором
  видны его прямые дети (по их слоям масштаба; если уровней нет — на один шаг), и центрирует на
  фигуре контейнера, а при её отсутствии — на его загруженных детях. `fitBounds` по полигону не
  используется: контейнер может быть кругом, иконкой или узлом без фигуры. Исключение — ребёнок-
  пространство или мнемосхема: вход открывает их холст, то есть другое детализированное
  пространство с иной «физикой» (как сейчас).
- **Регионы — только у мнемосхем.** `region_id` к контейнерам карты не добавляется: на реальной
  карте позиция объекта — его WGS84-точка, а «посадочное место» — сам полигон. Регионы со
  значениями на планах остаются темой §7 README (`plan-regions.md`), к контейнерам карты они не
  относятся.
- **Фокус — реальные карты.** Механизм единый для любого холста (у холста своя система
  координат), но принимается и проверяется на реальных координатах. Диаграммы не затрагиваются.
- **Ветка** `square-merge/m2.1-map-containers` от `master` после мержа M4. План-документ влит в
  `master` вместе с M4, на который он опирается.

## Шаги

1. **Холст как область запроса.**
   `proto/vms_map.proto`: `Box.canvas_id = 8` (без `reserved`); `Domain/GeoDTO/BoxDTO.cs`;
   `MapServiceImpl.Reads.ToBoxDto`. `GeoService.GetGeoAsync`: при заданном `canvas_id` фильтр по
   `canvas_id` заменяет прямоугольник (холст — это область), остальные фильтры (id, права)
   сохраняются. `GetByBox` при `canvas_id` не делает KMeans-обрезку >1000 фигур — холсту нужен
   полный состав уровня; `WatchBox`/`MapWatchPoller.PollBoxAsync` наследуют фильтр через `Box`.
   REST `api/map/objects/by-box` и `api/map/live` принимают canvas.
   Проверка: тесты VmsMap — две карты с пересекающимися координатами не смешиваются; права
   по-прежнему фильтруют; `dotnet build/test` зелёные.

2. **Камера на холсте ≠ ребёнок пространства.**
   Все чтения размещений и ориентиров берут холст из `geo_objects.canvas_id` вместо
   `markers.parent_id`: `SpatialDb.ListPlacementsAsync`, `RowInSpaceAsync`, `RemovePlacementAsync`,
   `PlacedReferenceAsync`, `EnsureLandmarksUsableAsync`, `ListCameraSpatialModelsAsync`,
   `BuildSpatialModelsAsync`. `UpsertPlacementAsync`: «старый холст» берётся из прежнего
   размещения; родитель-контейнер сохраняется, когда холст не меняется; при смене холста узел
   переносится под новое пространство. `Adapter/CameraNodeService.EnsureCameraAsync` уже оставляет
   размещённую камеру там, где она есть, — закрепить тестом.
   Проверка: камера под полигоном на карте; `GetCameraSpatialModel` находит её; список размещений
   сообщает холст; перенос reference-размещения на другую карту переносит узел; reconcile
   адаптера не возвращает его назад.

3. **Корректность `canvas_id` при переносе поддерева.**
   `MapDb.UpdateHierarchyAsync` пересчитывает `canvas_id` всему перенесённому поддереву
   (`GetSubtreeIdsAsync`), а не только переносимым узлам. После переноса тревоги пересчитываются
   существующим путём через `MapUpdateService.UpdateObjects`.
   Проверка: перенос контейнера с ребёнком между двумя холстами — `canvas_id` детей обновился;
   тревоги и права после переноса верны.

4. **Клиент: холст по `canvas_id`.**
   `src/hooks/useMapSpace.ts` (оператор) и `src/hooks/useMapChildren.ts` (админ) грузят
   `getByBox({…, canvasId})` и `getMarkersByIds` вместо `GetByParent`; состояния — как сейчас.
   `src/map/geo.ts`: `spaceBox` заменяется на область холста (или сохраняет бокс для поиска, но
   холст получает `canvasId`). Список размещений камер приходит с сервера уже с правильным холстом.
   SSE box-watch получает `canvasId`; id-watch не меняется. Рисуются дети любой глубины.
   Проверка: `npm run build && npm run lint`; вручную — фигура и камера под полигоном видны на
   холсте; фигура под полигоном на другом холсте не появилась.

5. **Уровни масштаба для всех.**
   Фигуры — как сейчас (`FiguresLayer`). Камера: уровень из точечной фигуры узла в ответе холста;
   маркер и конус скрываются вне диапазона. Ориентир: фигура (и жёлтый маркер в админке).
   Футпринт пространства: уровень из его полигона в ответе холста; вне диапазона не рисуется.
   Редактор: слой масштаба в `ObjectPropsEditor` для камер, пространств и ориентиров (`GetObjProps`
   уже отдаёт диапазон фигуры узла).
   Проверка: набор «город — районы, район — здания, деталь — камеры» скрывает и показывает каждый
   вид; узел без уровня виден на всех зумах.

6. **Кнопка «Войти».**
   В панели выбранного узла (`components/objects/ObjectPanel.tsx` или панель оператора) и в строке
   тревожного списка — действие для узла с детьми. Для узла на карте: повысить зум до минимального
   уровня его прямых детей (из загруженного справочника `levels`; если уровней нет — на один шаг) и
   центрировать на фигуре узла, а при её отсутствии — на его загруженных детях. `fitBounds` не
   используется. Для ребёнка-пространства или мнемосхемы — открыть их холст, как сейчас. Клик по
   карте ничего не приближает. i18n `en`/`es`.
   Проверка: выбор тревожного района → «Войти» увеличивает зум; проявляются здание, затем камера;
   для контейнера-иконки и контейнера-круга кнопка работает так же; футпринт пространства
   по-прежнему открывает план.

7. **Редактор: контейнеры.**
   Контейнером может быть любой узел — полигон, круг, иконка, объект без фигуры; нового вида нет.
   Новый объект создаётся под выбранным узлом, если он выбран в редакторе, иначе под пространством
   (как выбор родителя в Square); для камеры узел переносится под выбранный контейнер после записи
   размещения (шаг 2 сохраняет его при следующих записях на том же холсте). Существующий объект
   переносится действием «Переместить в…»: пространство или любой узел этого холста, с поиском по
   имени; перенос через `PUT /api/map/admin/objects` (`MapAdminController`) с сохранением `owner_id`
   у реплик. Тревожный контейнер-фигура получает тот же пульс `vms-alarm-pulse`, что и футпринт
   (`map/map.css`).
   Проверка: полигон «Район», здание и камеры явно вложены в него; камера внутри полигона, но не
   его ребёнок, переносится действием «Переместить в…»; иконка тоже держит детей; тревожный
   контейнер пульсирует.

8. **Документация.**
   `docs/plans/square-merge/README.md` §4.2/§4.3: холст — единица рисования, контейнеры, уровни
   для всех видов, диаграммы без изменений. `docs/maps-and-plans.md` (английский) — те же правила.
   `docs/plans/square-merge/m2.1-map-containers.md` — «Ход работы» по шагам.

9. **Приёмка.**
   `dotnet build dotnet/ta_vms.sln`, `dotnet test` (VmsMap — обязательно; остальные без
   регрессий), `npm run lint && npx tsc --noEmit && npm run build`. Живой сценарий Playwright:
   карта (реальные координаты) → район → здание → камера, вложенность задана деревом; у каждого
   свой уровень; тревога камеры (через `RetainEvent`/`UpdateStates`) красит здание и район на
   обзорном масштабе, камера скрыта; «Войти» увеличивает зум и проявляет детей; снятие тревоги
   возвращает цвета. Проверка прав (пользователь без `view` на контейнер его не видит). SSE
   обновляет тревоги без перезагрузки. Ничего не оставлено запущенным.

## Приёмка

Готово, когда:

- На реальной карте контейнер — любой узел с детьми (полигон, круг, иконка, объект без фигуры);
  вложенность задаётся только деревом, геометрия её не определяет.
- На обзорном масштабе дети скрыты по уровням, а тревога потомка красит и пульсирует контейнер;
  «Войти» увеличивает зум, и дети проявляются по своим уровням.
- Уровень масштаба задаётся любому узлу; узел без уровня виден всегда.
- Дерево показывает иерархию, тревожные счётчики и ведёт к объекту.
- Вход в пространство или мнемосхему открывает их холст — другое детализированное пространство;
  диаграммы, их регионы, глубина 0–3 и покраснение — без изменений.
- Схема БД не менялась; наведение, калибровка и ориентиры для камер под контейнерами работают.
- Сборки, тесты и линт зелёные; SSE без поллинга тревог.

## Открытые вопросы

- **Насколько далеко уводит «Войти».** Зум поднимается до минимального уровня прямых детей; при
  большом разрыве уровней это может быть резкий скачок. Уточнить на живой проверке.
- **Очень большой холст.** Пока холст грузится целиком; при тысячах фигур понадобится оконная
  загрузка по видимой области — тогда `Box.zoom`/прямоугольник снова пригодятся.
- **Явный перенос.** Геометрия не делает объект ребёнком: если перенос забыт, объект останется под
  пространством и появится на прежнем зуме. Действие «Переместить в…» должно быть заметным; запись
  размещения на том же холсте родителя не сбрасывает (шаг 2).
- **`UpdateObjects` и `owner_id`.** Общий перенос обнуляет `owner_id`, если он не передан; действие
  «Переместить в…» должно его сохранять (или сервер — не перезаписывать отсутствующий).
- **Узел без фигуры как контейнер.** С карты в него не войти — только из дерева или панели; центр
  для зума — его загруженные дети.
- **Камера на мнемосхеме.** Размещения камер остаются только в пространствах; реплики на
  мнемосхемах — как сейчас, без размещения.
