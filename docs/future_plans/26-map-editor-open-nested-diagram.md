# Редактор карты: вложенная диаграмма не открывается кликом по бумаге

Найдено при проверке M4 (2026-11-24) пробой в браузере.

**Что происходит.** В Admin → Maps открыть холст (`diag1` или `diag2`), кликнуть по вложенной
диаграмме на его бумаге — холст закрывается, вместо того чтобы открыть вложенную диаграмму.
Подпись вьюера обещает обратное: «A nested diagram is entered by picking it».

**Почему.** `DiagramViewer.pick` для `nodeKind === 'diagram'` зовёт `onOpen` → `selectNode`
(`SpaceEditor`), а тот смотрит `markersById[id]?.nodeKind` в сторе `objects.markers`. Дети
открытой диаграммы приходят чтением `diagrams.content` и в `objects.markers` не попадают (в него
пишут чтения канвы и списка узлов), поэтому `nodeKind` неизвестен, и `selectNode` уходит в ветку
`openDiagram(null)` — «вернуться на карту». Через строку дерева слева та же диаграмма открывается:
там `openDiagram(marker.id)` зовётся с маркером из дерева.

**Почему это важно.** Демо и документация описывают вход в холст кликом по бумаге; дерево — обходной
путь. В parity-прогоне это было незаметно: там вложенную диаграмму создавали в той же сессии, и её
маркер уже лежал в сторе.

**Как чинить.** Решать по тому, что показывает открытая диаграмма: `selectNode` должен считать
узел диаграммой, если он есть в `diagrams.content` открытого холста (или в маркерах, загруженных
этим чтением), а не только в `objects.markers`. Второй вариант — на клике не полагаться на стор, а
открывать диаграмму по `nodeKind` из контента (`pick` уже получает маркер из `content`). Заодно
проверить оператора: `MapsOperatorPanel` грузит маркеры канвы сам, и там поведение может отличаться.
