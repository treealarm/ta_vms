# Что многомашинное развёртывание оставляет открытым в сети

Найдено 2026-10-23 при постройке разделения core/node: Consul разрешает app id, Dapr Sentry
выдаёт сертификаты sidecar'ов по токену на app id (его валидатор `jwks`), а API, метрики и
app-порты каждого sidecar'а остаются на loopback
(`../ta_install/docker-compose.distributed.yml`, `../ta_install/scripts/distributed.sh`). Вот что
осталось.

- **healthz и метрики Sentry и placement слушают на всех адресах.** Sentry 1.18.7 игнорировал и
  `--healthz-listen-address 127.0.0.1`, и `--metrics-listen-address 127.0.0.1` (в логе было
  `[::]:<port>`), а placement на тестовой машине Windows слушает `[::]:6051`, хотя
  `windows/config/services.json` даёт ему `--healthz-listen-address 127.0.0.1`. Только чтение, но
  в LAN им быть не следует: выяснить почему или закрыть в firewall core.
- **Keycloak доступен по обычному HTTP с каждой машины, где есть web** (он слушает на адресе
  core, раз web есть на каждой машине): пароли пользователей при входе и пароль администратора
  при управлении пользователями идут по LAN открытым текстом. Нужен HTTPS на Keycloak с
  сертификатом core и `KEYCLOAK_URL` на `https://`.
- **API (9997) и WHEP (8889) каждого MediaMTX слушают на адресе своей машины** — теперь так и
  задумано: VmsUtils на core спрашивает каждый, кто смотрит, а web каждой машины передаёт WHEP к
  MediaMTX камеры. Оба отвечают только с паролем `vms_read`, который есть у каждой машины (ниже).
- **PostgreSQL и RabbitMQ доступны с узлов открытым текстом**, за своими паролями
  (`distributed.sh` отказывается от значений по умолчанию). TLS для обоих: `hostssl` и `ssl=on` с
  сертификатом core; AMQPS для RabbitMQ. Роль для узлов с доступом только к state store и `ta_fs`,
  если миграциям `ta_fs` не нужно больше. Эта роль — то, что ограничивает узел сегодня: с паролем
  PostgreSQL core он читает каждый секрет VmsCfg, включая пароли MediaMTX. Убрать
  `VMS_MEDIAMTX_*` из пакета ничего не закроет: `vms` узла получает строку MediaMTX, включая
  пароль на чтение, из VmsCfg, и его собственный MediaMTX работает на этих аккаунтах.
- **У Consul пока нет ACL**, только шифрование gossip: всё, что дотянется до HTTP API агента
  (loopback машины развёртывания), может регистрировать и снимать сервисы. ACL с default deny,
  токен на агент и отдельный на регистрацию сервисов.
- **Токены не истекают, а удаление узла их не отзывает.** Токены узла — это его учётные данные;
  отозвать один — значит сменить ключ подписи в JWKS Sentry и выдать новые токены каждой машине.
  Отдельный ключ на узел (несколько ключей в JWKS, VmsCfg подписывает ключом самого узла) позволил
  бы Administration → Deployment отзывать удаляемый узел. Ключ подписи сейчас читает VmsCfg,
  который делает пакеты: на Windows служебная учётная запись может прочитать `core\jwt.key`, как
  уже читает ключ issuer Sentry и каждый пароль своего окружения.
- **Пакет узла едет из web core по обычному HTTP** (`POST /api/deployment/join`), со всеми
  паролями core внутри. HTTPS на web_srv с сертификатом, который установщик узла может проверить
  (отпечаток показывается в web и спрашивается установщиком), закрыл бы и подслушивающего, и
  машину, выдающую себя за core.
- **У вступления нет ограничения частоты.** При закрытом enrollment пароль проверяется в
  Keycloak, у которого есть своя защита от перебора (в поставляемом realm она выключена); при
  открытом угадывать нечего. Лимит на `/api/deployment/join` по адресу клиента дёшев, когда
  появится причина.
- **Узел на площадке, вступающий в core в облаке** (core арендатора в Kubernetes): каждый порт из
  списка выше должен был бы пересечь интернет. Нужен отдельный проект — туннель на узел или
  sidecar'ы узла через один шлюз core — прежде чем это предлагать.
- **Firewall по роли** на Windows (`Install-TaVms.ps1`) и его описание для Linux, где
  опубликованные порты Docker обходят ufw — с `network_mode: host` не обходят, и это помогает.
- **Машины развёртывания должны быть в одной подсети**: правила firewall Windows открыты для
  `LocalSubnet`, а PostgreSQL core пускает `samenet`. Узлу за роутером нужно назвать диапазоны
  адресов развёртывания вместо этого — в установщике и в `pg_hba`.
