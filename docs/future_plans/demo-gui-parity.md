# Примитивы конфигурации должны собираться в GUI

Найдено 2026-11-03 при завершении M2.2, по просьбе пользователя: администратор должен уметь
собрать в GUI каждый **примитив конфигурации**, из которых состоит мир, — карту, план, тип
диаграммы, регион, диаграмму, точку, иконку, размещение камеры, права, уровень, видеостену.
Демо — проверка этого свойства, а не отдельная возможность: `DemoSeeder` пишет мир только через
обычные сервисы, поэтому всё, что он умеет, обязано иметь путь в GUI. Если примитив доступен
только из кода, продукт умеет его выражать только кодом.

Это не про замену сидера: демо остаётся переустанавливаемым кодом. Это про полноту GUI.

## Аудит: примитив → путь в GUI

| Примитив (что пишет сидер) | Где в GUI |
|---|---|
| Карта, план, вложенный план; вид, футпринт, этаж, порядок | Admin → Maps → «+» → Map / Plan / вложенный план (`SpaceForm`), поля и футпринт — `SpaceEditor` |
| Картинка плана с углами (`SavePlanAsync`) | `SpaceEditor` → «Plan picture», загрузка файла |
| Файл: фон типа, иконка, картинка плана | загрузка в редакторе типа, в свойствах объекта, в плане |
| Уровень зума (`LevelService.UpdateAsync`) | `MapDictionariesDialog` → Scale layers |
| Тип диаграммы: имя, фон, регионы, стили (`DiagramTypeService`) | `MapDiagramTypesDialog` с визуальным редактором регионов (M2.2, шаг 2) |
| Диаграмма в точке пространства (`CreateGeo`) | список узлов → «+» (`addDiagram` ставит в центр вида), затем ручка точки перетаскивается |
| Холст диаграммы, её тип, регион, картинка | `DiagramElementEditor` |
| Иконка узла, подпись, размер, поворот, зум-слой (`UpdateVisual`, `zoom_level`) | `ObjectPropsEditor` |
| Дочерняя диаграмма внутри диаграммы, регион/собственный прямоугольник | `DiagramViewer` → «New diagram»; перетаскивание в регион или поля `DiagramElementEditor` |
| Размещение камеры (`UpsertPlacementAsync`) | Admin → Maps → Devices (клик ставит картинку), `SpaceEditor`; калибровки — `GroundCalibrationDialog`, `PtzGeoCalibrationDialog` |
| Права (`RightService.Update`) | `ObjectRights` в редакторе пространства |
| Видеостена: раскладка, слоты, камеры | Admin → Monitors |
| Настройки входа/реле (`device_settings`: имя, охрана, `trigger_on`) | Admin → Cameras → **Devices** (вкладка устройства); ONVIF settings остаётся настройкой железа |
| Подписка на событие (`event_subscriptions`: селектор и действия) | Admin → Event routing (`EventSubscriptionsPanel`, JSON-селектор с серверной валидацией) |
| Демо-мир и его стена | Admin → Deployment, нижний блок (установить/удалить); `DEMO_CONFIG` ставит то же при старте |

## Что примитивом не является

1. **Состояния (`UpdateStates`).** Состояние пишет владелец — VmsFs (обрыв источника), retention,
   ONVIF. Демо больше не пишет синтетических состояний: единственная его строка — `CONNECTED` на
   порту, чтобы перезаписать `DISCONNECTED` прежних версий мира. Вручную состояние не ставится и
   не нужно — пользователь получит настоящую тревогу, отключив камеру.
2. **Значения (`temp`/`humidity`).** `DemoValueFeeder` — заглушка до M2.3; в GUI редактора значений
   нет и не планируется: значения приходят от устройств. После M2.3 их место займут реальные
   параметры ONVIF (геолокация, реле).

Это данные времени выполнения, а не конфигурация: их отсутствие в GUI — не пробел.

## Что заметить и поправить

- **Тип самой диаграммы правится неочевидно.** Он меняется только если кликнуть по «бумаге»
  открытой диаграммы — это выбирает корень и показывает `DiagramElementEditor`. При этом список
  «Region» предлагает регионы самой диаграммы, что бессмысленно. Нужен явный выбор типа для
  открытой диаграммы (поле в тулбаре или в редакторе корня) и скрытый «Region» у корня.
- **Новая диаграмма ставится в центр вида, а не по клику.** Не блокер (точку можно перетащить),
  но для сборки мира вручную неудобно; можно добавить режим «поставить диаграмму кликом».
- **Проверка «собрать мир только через GUI»** не сделана: нужен одноразовый Playwright-прогон,
  который проходит примитивы из таблицы (карта → план → тип → диаграммы → камеры → стена), а
  затем сверяется с ожиданиями `tests/demo/check_demo.py`. Состояния и значения в нём
  пропускаются по причине выше.

## M2.4e: что закрыто и что осталось

Закрыто: демо-установка пишет `device_settings` (датчик `sim-ptz/input`: `arm_mode=armed`,
`alarm_enabled=true`, `trigger_on` по полярности провода) и подписку `demo-sensor-recording` через
те же `CfgService`-пути, что и GUI; у обоих есть GUI — вкладка **Devices** на странице камеры и
**Admin → Event routing**. Порт больше не тревожит: единственная строка состояния в мире —
`CONNECTED`, её владелец — не демо.

Осталось:

- **Playwright-прогон «собрать мир только через GUI»** из раздела выше всё ещё не сделан. Теперь
  в него входят вкладка Devices и панель Event routing; сверка — с `tests/demo/check_demo.py`.
- Демо-подписку можно удалить в Event routing, и до переустановки мира демо-реакция пропадёт.
  Пометки «принадлежит демо» в UI нет; повторная установка возвращает правило (фиксированный id).
- Полярность входа в демо известна из проводки OnvifSim и записана кодом. Если на камере
  полярность меняется, GUI её показывает и правит (idle state в ONVIF settings, trigger — в
  Devices), но демо-мир этого не перепроверяет.

## Когда браться

Playwright-прогон — когда UI карты и устройств перестанет меняться каждый майлстоун, то есть
после M2.6. GUI-редактор состояний для отладки по-прежнему не нужен: состояния — данные
владельцев.
