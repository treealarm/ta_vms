# Демо должно собираться в GUI, а не только сидером

Найдено 2026-11-03 при завершении M2.2, по просьбе пользователя: всё, что `DemoSeeder` пишет
через сервисы, администратор должен уметь сделать в GUI. Демо не имеет права быть единственным
способом построить такой мир — иначе продукт умеет выражать его только кодом.

Это не про замену сидера: демо остаётся переустанавливаемым кодом. Это проверка полноты GUI.

## Что уже делается в GUI (проверено по коду, отдельные пути — вживую)

| Операция сидера | Где в GUI |
|---|---|
| Карта, план, вложенный план, вид, футпринт | Admin → Maps → «+» → Map / Plan / вложенный план (`SpaceForm`), футпринт и вид правятся там же (`Footprints`, `SpaceEditor`) |
| Картинка плана с углами (`SavePlanAsync`) | `SpaceEditor` → «Plan picture», загрузка файла |
| Словарь уровней (`LevelService.UpdateAsync`) | `MapDictionariesDialog` → Scale layers |
| Тип диаграммы: имя, фон, регионы, стили (`DiagramTypeService`) | `MapDiagramTypesDialog` с визуальным редактором регионов (M2.2, шаг 2) |
| Диаграмма на пространстве в точке (`CreateGeo`) | список узлов → «+» (`addDiagram` ставит в центр вида), затем ручка точки перетаскивается; тип, регион, холст и картинка — `DiagramElementEditor` |
| Иконка узла, подпись, поворот, зум-слой (`UpdateVisual`, `zoom_level`) | `ObjectPropsEditor` (иконка загружается файлом, зум-слой — из словаря) |
| Дочерняя диаграмма внутри диаграммы, регион/прямоугольник | `DiagramViewer` → «New diagram»; перетаскивание в регион или поля `DiagramElementEditor` |
| Камеры и размещения (`UpsertPlacementAsync`) | Admin → Cameras + панели размещения в `SpaceEditor` |
| Права (`RightService.Update`) | `ObjectRights` в редакторе пространства |
| Видеостена (`UpsertMonitor`, `SetMonitorCameras`, слоты) | Admin → Monitors |

## Где GUI не может повторить демо — и почему

1. **Состояния (`UpdateStates`).** В GUI нет и не должно быть «поставить узлу состояние»: состояние
   пишет его владелец — VmsFs (обрыв источника), retention, ONVIF. `DISCONNECTED` на порту —
   синтетическая строка демо; вручную её не поставить. Пользователь получит настоящую тревогу,
   отключив камеру (VmsFs → `DISCONNECTED`), а не порт.
2. **Значения (`temp`/`humidity`).** `DemoValueFeeder` — заглушка до M2.3; в GUI редактора значений
   нет и не планируется: значения приходят от устройств. После M2.3 их место займут реальные
   параметры ONVIF (геолокация, реле).

Это ограничения данных, а не структуры мира: всё, что делает демо как конфигурацию, в GUI есть.

## Что заметить и поправить

- **Тип самой диаграммы правится неочевидно.** Он меняется только если кликнуть по «бумаге»
  открытой диаграммы — это выбирает корень и показывает `DiagramElementEditor`. При этом список
  «Region» предлагает регионы самой диаграммы, что бессмысленно. Нужен явный выбор типа для
  открытой диаграммы (поле в тулбаре или в редакторе корня) и скрытый «Region» у корня.
- **Новая диаграмма ставится в центр вида, а не по клику.** Не блокер (точку можно перетащить),
  но для сборки мира вручную неудобно; можно добавить режим «поставить диаграмму кликом».
- **Проверка «собрать демо только через GUI»** не сделана: нужен одноразовый Playwright-прогон,
  который повторяет шаги из таблицы выше (карта → план → тип → диаграммы → камеры → стена), а
  затем сверяется с ожиданиями `tests/demo/check_demo.py`. Состояния и значения в этом прогоне
  пропускаются по причине выше.

## Когда браться

После M2.3 (там значения перестают быть синтетикой). Тогда же решить, нужен ли GUI-редактор
состояний для отладки — сейчас его нет сознательно.
